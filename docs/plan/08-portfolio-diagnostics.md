## 0. 结论（先给判定，再给理由）

| 问题 | 判定 |

## 2. 现状取证

### 2.1 全库没有任何跨标的的资金分配

`run_signaled` 逐标的循环，每个标的独立走 `_drafts → stage_draft`。`block_reason` 的每一个维度（`cash_reserve_pct` / `max_symbol_pct_nav` / `max_short_opt_margin_pct` / `max_orders_per_day`）都是**单标的或单腿**口径。`open_quantity` 只看单标的市值上限。

⇒ **"标 A 该拿多少、标 B 该拿多少"这个问题在代码里不存在。** 谁先被遍历到谁先拿钱，而遍历顺序是 `settings.watchlist` 的字面顺序。

### 2.2 期望收益在这套数据上不可估计（这是否决 MVO 的硬理由）

实测：每个标的 `ib-daily` 恰好 **60–61 根**，区间 `2026-07-17 → 2026-10-09`，约 **0.24 年**。

年化均值的标准误：

```
SE(μ̂_annual) = σ_annual / √T_years
T = 0.24 年  ⇒  SE ≈ σ_annual / 0.49 ≈ 2 × σ_annual
```

取一个 30% 年化波动的标的（本池子里 35% 带 `HIGH_BETA`，30% 属保守）：

| 量 | 值 |
| --- | --- |
| μ̂ 的 95% 置信区间半宽 | ≈ 1.96 × 2 × 30% ≈ **±118 个百分点** |
| 要估计的股权风险溢价 | ≈ **5 个百分点** |
| 信噪比 | 约 **1 : 24** |

⇒ 任何把历史均值喂给优化器（均值-方差、最大 Sharpe、风险平价）的做法，都会产生 **Markowitz 的"误差最大化"**：权重最大的资产恰好是估计误差最大的资产。这不是精度问题，是**符号都不可信**问题。

并且这还是在 `D1/D3` 落地之前的数字。即便补到 252 根（1 年），SE 仍等于 σ 本身（±59 个百分点），**依然不可用**。要让 SE 降到 5pp 以内，需要 `(σ/0.05)² ≈ 36 年` 的数据。

### 2.3 组合的因子集中度（实测，这是真正的问题）

31 个标的的 classifier 分布（`symbol_phases.classifiers`）：

| 桶 | 标的数 | 占 watchlist |
| --- | --- | --- |
| `AI_NARRATIVE` | **22** | **71%** |
| `MEGA_CAP` | 13 | 42% |
| `HIGH_BETA` | 11 | 35% |
| `SEMIS` | 9 | 29% |
| `MAG7` | 4 | 13% |
| `DIVIDEND` | 3 | 10% |
| `DEFENSIVE` | **2**（GLD、T） | **6%** |
| `CYCLICAL` / `STRONG_FCF` / `WEAK_MARGIN` | 6 / 3 / 2 | — |

等相关系数下的**有效独立注数**（`N_eff = N / (1 + (N−1)ρ)`），对 `AI_NARRATIVE` 的 22 个标的：

| 压力相关性 ρ | N_eff |
| --- | --- |
| 0.3（平静市） | 3.4 |
| 0.5 | 1.9 |
| 0.7（压力市） | **1.4** |

⇒ **watchlist 的 71% 在压力下约等于 1.4 个独立的注。** 而"不做 AI 叙事"的替代品只有 GLD 与 T 两个。这意味着：无论 I1/I2/I3 多严密，**系统仍可能在 22 个 AI 名字上同时被指派**，而每一笔单独看都完全合规。

这是同类工具（Option Income Tools 等）用"per-sector / per-correlation-cluster exposure"处理的问题，也正是用户问的这张图**唯一真正值钱的用途**。

### 2.4 CML 的锚点不存在

```
SELECT DISTINCT symbol FROM market_bars WHERE symbol IN ('SPY','QQQ','IVV','VOO','VTI','IWM','DIA');
→ 0 行
```

watchlist 里没有任何宽基指数（最接近的是 `SMH`/`IGV` 两个行业 ETF，以及 `GLD`）。因此：

- **CML 画不出来** —— 它需要"市场组合"的 (σ_m, E[r_m])，两者都没有序列。
- 步 4 的 `REGIME_RISK_OFF`（D18 默认 `SPY`）也会因此常年返回 `regime_unknown` —— **这是同一个缺口，本册要一并解决**。

### 2.5 短波动率的收益分布使方差失效

卖 CSP 的收益形态是"到期前收租、被指派后转为持股"：上方收益被截断在权利金，下方是到行权价为止的近似线性敞口。分布特征是**负偏 ＋ 高峰度**。后果：

- 方差（及 Sharpe）**系统性低估尾部**、**高估被放弃的上行**；
- 一个从未被指派过的深 OTM 短 put，其历史方差会很小，于是被方差类指标评为"高效"——**恰好在它最危险的时候**；
- 评审 §4 自己给出的判据（"a CSP strike is a limit buy order you are happy to have filled"）已经说明：CSP 不是"一个带 beta 的资产权重"，而是**一张有条件的限价买单**。把一张限价买单模型化成组合权重，是把它的语义反过来了。

### 2.6 新发现的缺陷：I2 是 ticket 级，不是 cycle 级

`stage_draft` 在求值时读 `account_marks` / `nav_marks` 的**最新快照**：

```python
mark = SELECT cash, margin FROM account_marks WHERE account_id = %s ORDER BY day DESC LIMIT 1
```

而 `stage_draft` 只写 `drafts` 表，**不产生 `orders`**（订单在 `decide()` 批准时才落）。`account_marks` 只在 IB session 同步时更新。

⇒ 同一 cycle 内先后 stage 的 N 张 ticket，**每一张看到的 `cash` 都是同一个未扣减的值**。步 2 的 I2 只把这个值在**一张 ticket 内部**汇总，**没有跨 ticket 的累计**。因此"两张 ticket 各自合规、合起来透支"这个漏洞，I2 拦不住。

这与 §2.1（无跨标的分配）是同一个病：**系统只有"每一笔都对"，没有"这一轮合起来还对"。**

## 3. 变更逻辑 spec

### 3.1 进核心逻辑的三条约束

三条都是**约束**，不是优化器。它们共用同一个"cycle 累加器"，检查点都在步 2 的 `block_ticket_reason` 之内（扩展其入参），因此不新增调用点。

#### I4 — cycle 级资金配给

```
cycle_start:
  baseline := 读一次 account_marks.cash / margin、nav_marks.last_nav    # 一次，不是每腿
  acc      := baseline
for ticket in ordered_tickets:            # 顺序 = 优先级，不是 watchlist 顺序
  merged := acc + Σ(ticket 的腿)
  若 merged 击穿 cash_reserve_pct / max_symbol_pct_nav /
     max_short_opt_margin_pct / max_orders_per_day 任一项:
        整张 ticket 全部腿 blocked，原因 ticket 级
  else:
        acc := merged                     # 后续 ticket 看到的是已扣除的余量
        ticket 通过
```

**票序（与现状最大的差别）**：按**动作优先级**排序，而不是 watchlist 字面顺序：

```
1. 减仓类（CLOSE / ROLL，来自告警态与 manage_book）   —— 先腾出空间
2. dip_long（[BUY, OPEN_CSP]）
3. high_cc（[OPEN_CC]）
4. 其余
```

**为什么必须排序**：否则"谁先遍历到谁先拿钱"，而 watchlist 顺序是一个**没有金融含义的常量**。这在有配给的系统里是致命的设计缺陷 —— 一个 symbol 在 watchlist 里往上挪一行就能改变谁被开仓。

#### I5 — 因子桶集中度上限

```
bucket(symbol) := symbol_phases.classifiers 的全部命中项        # 全量归属，保守
exposure(leg)  := CSP:  strike × multiplier × contracts          # 现金备兑口径
                  CC:   shares × avg_price                       # 权益占用口径
                  BUY:  limit × quantity
约束:  Σ exposure over bucket b  /  NAV  ≤  max_bucket_pct_nav
```

两个设计选择：

1. **全量归属而非唯一归属**：一个 `SEMIS, AI_NARRATIVE, MEGA_CAP` 的标的**全额计入三个桶**。这是保守方向，且与风险系统对多映射资产的惯常做法一致。若改用"按优先级取第一个桶"，`AI_NARRATIVE` 与 `SEMIS` 的排序会变成一个需要长期维护的、无法验证的常量。
2. **不用相关性矩阵估计**：31×31 的样本协方差在 60 根样本下条件数极高，求逆会把噪声放大。改用**桶 + 固定的压力相关性下限**（D31）来表达"同桶即高度相关"，这是可解释、可审计、且不会随样本漂移的。

#### I6 — 同时被指派暴露

```
likely_assignment := 空 put 且 |Δ| ≥ assign_delta        # |Δ| 是 P(ITM) 的标准近似
assignment_capital := Σ (strike × multiplier × contracts) over likely_assignment
约束1: assignment_capital / NAV ≤ max_assign_pct_nav
约束2: cash − assignment_capital ≥ min_cash_after_assign_pct × NAV
```

**约束 2 是本册最有用的一条**：它把评审 §4 那句"行权价是你乐意被成交的限价买单"变成**算术**。如果吃完全部近似指派后现金会掉到下限之下，那这些 put 就不该同时存在 —— 无论每一张单独看起来多漂亮。

**|Δ| 的口径声明（必须随结果一起打印）**：`|Δ| ≈ P(ITM)` 是标准近似，对 call 略偏保守（`N(d1) > N(d2)`）。它是**近似**，不是概率模型；审计里记 `prob_source="delta_proxy"`。

**必须画进图里的参考线**：

- **CAL（本账）**：从 `(0, r_f)` 过组合合计点的一条线。它的**斜率就是本账的收益/风险比**，是与 CML 比较的唯一有用输出 —— **一个数**。
- **CML（市场）**：从 `(0, r_f)` 过市场点。**当前画不出来**（§2.4 无指数序列）→ 图中打印 `market_unknown`，并在 D29 拍板后由"把指数纳入拉取范围"补齐。
- **桶上限线**：图 B 上的 `max_bucket_pct_nav` 水平线（来自 I5）。这是图从"好看"变成"能推动动作"的地方。

**必须显式**不画**的三样（并打印理由）**：

| 不画 | 打印的理由 |
| --- | --- |
| 有效前沿曲线 | `μ inestimable from 60 bars (SE≈2σ)` —— 画一条前沿等于宣称"可以按它增配以变优"，而这个宣称在 §2.2 下不成立 |
| 切点组合 / 最优权重 | `no tangency: market portfolio series absent` ；即便有，切点由 μ 决定，而 μ 不可估 |
| 任何"目标配置" | 本系统不做优化配置；决策来自步 6 的迁移表与 I4/I5/I6 的约束 |

**面板必须常驻的注记**（防止被误读为优化器输出）：

```
σ = RV20 (realized, NOT implied)  · 样本: 60 bars/symbol (0.24y)
y   = annualized premium / capital at risk   ← 是最大收益, 不是期望收益
μ   not estimated             ·  EF & tangency omitted by design
```

> 注：最后一行"y 是最大收益不是期望收益"是**必须**的。卖 put 的最大收益是权利金，而期望收益要减去期望赔付 —— 若不标注，图 A 会把 ATM 短 put 显示为"低 σ 高收益"的最优点，而那恰好是**被指派概率最高**的一档。这是本册里最容易犯、也最危险的误读。

### 3.3 为什么 CML / CAL / EF 不能进核心逻辑

| # | 经典假设 | 本账的实际情况 | 后果 |
| --- | --- | --- | --- |
| 1 | 收益近似联合正态 / 椭圆分布 | 短期权＝负偏 ＋ 高峰度 | 方差低估尾部、高估被放弃的上行；深 OTM 短 put 在爆掉前一直"高效" |
| 2 | 只用均值和方差即可刻画偏好 | 收益被截断、风险是"被指派后持股"的路径依赖 | 二次效用函数不描述这套策略的目标（收租 ＋ 乐意接货） |
| 3 | μ 可从历史估计 | 60 根 ⇒ SE(μ) ≈ 2σ（§2.2） | 误差最大化：权重最大的资产＝误差最大的资产 |
| 4 | 可在 r_f 上自由加杠杆到切点组合 | 零售 IBKR ＋ 期权保证金是**逐仓规则**，不是平滑的直线 | CAL 的直线是虚构的；"加杠杆到切点"不存在对应动作 |
| 5 | 单期、无制度切换 | 整个策略是**制度驱动**的（回调→Long+CSP，高位→CC） | 静态优化器会在引擎该减仓的时刻说"这两只 Sharpe 最高，继续持有" |

⇒ 结论：**CML/CAL 只作为"一个参照斜率"和"一张图的两条线"存在，不作为优化目标。EF 与切点完全不进系统。**

## 6. 明确不做

- **不做组合优化**：不实现均值-方差、最大 Sharpe、风险平价、Black–Litterman。理由是 §2.2 与 §3.3 的五条，不是工期。
- **不估计期望收益**：任何路径都不得以历史均值作为前瞻收益输入。
- **不估计 31×31 协方差矩阵**：改用桶 ＋ 压力相关性下限（D31）。
- **不用面板驱动决策**：面板是只读的；约束由 I4/I5/I6 在代码里强制。看图做决定是人的动作，不是系统的。
- **不画 EF 与切点**（§3.2）。
- **不改步 2 的 I1/I2/I3**：本册只**新增** I4/I5/I6，并把 I2 的检查点扩到 cycle 作用域。
- **不引入新的市场数据供应商**：指数只需并入既有 IB 拉取窗口（与步 4 D18 同一处）。

## 7. 风险与回滚

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| I5 立刻变成紧约束 | 现有 71% 的 `AI_NARRATIVE` 会让 35% 上限几乎立即拦住新开仓 | 这是**预期的**信号：说明集中度已是真问题。若你希望"先建仓再收敛"，D32 可临时放宽到 60%，并在面板上保留原上限的参考线，使偏离可见 |
